# AI コーディングツールで「公開前チェック」を使う

アプリを公開する前に、お使いの AI に「**公開前チェックをしてください**」と頼むだけで、情報漏えいにつながる問題がないかを確認できるようにする設定です。

- 費用：無料
- プログラミングの知識：不要（設定も AI に頼めます）
- チェックの中身：プロジェクトのファイルを読むだけです。コードを実行したり、プロジェクトの内容を外部に送ったりしません
- ご注意：このチェックは QA.JP.AI の認証ではありません。安全を保証するものでもありません。公開前に、よくある事故の原因を見つけるためのものです

## チェックの仕組み

1. **ツールが検査します。** データベースのアクセス制御（R01）と、秘密のキーの扱い（R02）を、根拠を示して判定します。
2. **AI が残りを確認します。** ツールが検査しない項目（R03〜R15 など）を、AI がコードを読んで確認します。報告では「AI による確認」と明記し、ツールの結果と区別します。
3. **あなたに確認をお願いする項目があります。** 管理画面の設定など、コードだけでは判断できないことは、どこを見ればよいかをお伝えします。

## 設定のしかた

### Claude Code をお使いの場合

**AI に頼む場合**：Claude Code に、次のように頼んでください。

> QA.JP.AI の公開前チェックのスキルを、このプロジェクトに設定してください。
> https://github.com/QAJPAI/qa-jp-ai-scanner/tree/main/integrations/claude-code/skills/qa-jp-ai-pre-release-check の SKILL.md を、`.claude/skills/qa-jp-ai-pre-release-check/SKILL.md` として保存してください。

**自分で設定する場合**：`claude-code/skills/qa-jp-ai-pre-release-check` フォルダーを、プロジェクトの `.claude/skills/` の中にコピーします。すべてのプロジェクトで使う場合は、ホームフォルダーの `.claude/skills/` にコピーします。

### Cursor・Codex・Windsurf など、AGENTS.md を読む AI をお使いの場合

[セキュリティ基本ルール](../rules/security-rules.ja.md)の「ここから」から「ここまで」までを、プロジェクトの `AGENTS.md` に追加してください（AI に「この内容を AGENTS.md に追加して」と頼めます）。作る段階で守るべきルールと、公開前チェックの手順の両方が入っています。

### Lovable・Bolt など、コマンドを実行できないサービスをお使いの場合

[セキュリティ基本ルール](../rules/security-rules.ja.md)を、AI への指示（ナレッジやプロジェクトの指示）に入れてください。公開前チェックを頼むと、AI が自分で確認します。この場合、**ツールによる検査は行われません**。より確かな確認が必要なときは、コードを GitHub などに書き出し、手元で下のコマンドを実行してください。

### コマンドで直接使う場合

Node.js 22 以上が必要です。プロジェクトのいちばん上のフォルダーで実行します。

```
npx --yes github:QAJPAI/qa-jp-ai-scanner#v0.6.0 check .
```

| オプション | 内容 |
|---|---|
| （なし） | 日本語のレポートを表示します |
| `--for-ai` | AI コーディングツールに渡す形式で表示します |
| `--json` | 機械で読める形式で表示します |
| `--fail-on P0` | 「至急」の問題があれば、終了コード 3 で終わります（自動テストで公開を止める用途） |
